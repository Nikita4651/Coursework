## PL-02 Инструменты и обоснование

1. Java + Selenide — UI-тесты, удобно для Page Object.

2. JUnit 5 — запуск тестов, привычная структура.

3. Gradle — сборка и запуск тестов; у меня уже есть опыт с build.gradle и настройкой зависимостей.

4. Allure — отчёты по тестам (красивые репорты с шагами, вложениями, скриншотами).

5. JDBC + JUnit (или простой DAO) — проверка записей в БД после теста. Это закрывает требование «запросы в базу».

6. Docker / Docker Compose — локально можно поднять MySQL, чтобы тесты были воспроизводимыми.

7. Git — публичный репозиторий, README с инструкцией запуска.

Итоговый ожидаемый результат; В обосновании нет «воды»: каждый пункт связан с конкретным требованием курсовой (UI‑тесты, проверка БД, отчёты, воспроизводимость).


## PL-03 Риски и оценка времени


1. База данных не успевает запуститься → тесты падают с ошибкой соединения. Решение: добавить ожидание (healthcheck) использовать библиотеки типа Testcontainers (если разрешено).

2. Разные СУБД (MySQL vs PostgreSQL) → SQL-синтаксис и типы данных отличаются. Решение: писать параметризированные тесты или отдельные конфигурации.

3. Симулятор банковских сервисов перегружен → таймауты. Решение: повторные попытки (retry) или увеличение таймаутов.

4. Проблемы с сетью/IP в логах → сложно отлаживать. Решение: фиксировать свой IP и искать логи по нему.

Итоговый ожидаемый результат; Риски привязаны к этапам работ (настройка, написание тестов, прогон), чтобы было понятно, на каком этапе что может пойти не так.
 


## PL-04 Оценка


1. Планирование: 4–10 часов.

2. Написание тестов (28-32 кейсов): 12–26 часов.

3. Настройка Allure, Docker, README: 8–18 часов.

4. Прогон, оформление баг-репортов, отчётов: 8–20 часов.

Итого: ориентировочно 42–76 часов (с учётом рисков и отладки).

Итоговый ожидаемый результат; Итоговый интервал: 42–76 часов с обоснованием разброса (отладка, нестабильность симулятора, настройка Docker).
Оценка привязана к количеству кейсов (20–22) и сложности проверок (UI + БД + логи).
Указано, что в оценку заложены риски (перезапуски, поиск ошибок, правка сценариев).
